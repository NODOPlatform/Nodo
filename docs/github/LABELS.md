# Labels — NODO

## Etiquetas oficiales

| Label | Color | Cuando usar |
|-------|-------|-------------|
| `good first issue` | `#7057ff` | Tareas ideales para nuevos colaboradores. Scope pequeno, contexto minimo. |
| `bug` | `#d73a4a` | Algo no funciona como deberia. |
| `enhancement` | `#a2eeef` | Mejora a funcionalidad existente. |
| `connector` | `#0e8a16` | Crear o mejorar un conector de la Red NODO. |
| `frontend` | `#1d76db` | Cambios en UI, componentes, paginas, estilos. |
| `backend` | `#5319e7` | Cambios en stores, libs, Supabase, logica de negocio. |
| `AI` | `#fbca04` | Cambios en el motor Assist, clasificadores, extractores. |
| `maps` | `#006b75` | Cambios en MapView, Leaflet, geolocation. |
| `documentation` | `#0075ca` | Documentacion, onboarding, guias, traducciones. |
| `priority-high` | `#b60205` | Urgente. Afecta produccion o bloquea otras tareas. |
| `priority-medium` | `#e4e669` | Importante pero no urgente. |
| `priority-low` | `#c5def5` | Nice to have. Sin deadline. |

## Reglas

- Todo issue debe tener al menos un label de tipo (`bug`, `enhancement`, `connector`, etc.).
- Los labels de prioridad son opcionales. Usar solo cuando sea necesario priorizar.
- `good first issue` se combina con el label de tipo: `good first issue` + `frontend`.
- No crear labels nuevos sin aprobacion del equipo core.
